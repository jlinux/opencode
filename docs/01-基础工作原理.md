# OpenCode 基础工作原理

## 1. 总体架构

OpenCode 是一个开源 AI 编程助手，支持终端 UI (TUI)、Web UI 和桌面应用（Tauri）。整体架构为**事件驱动的多层架构**：

```
┌──────────────────────────────────────────────────────────────┐
│                    前端 UI 层                                 │
│   TUI (SolidJS + OpenTUI)  │  Web UI (SolidJS + Vite)       │
│   Desktop (Tauri 2)        │                                 │
├──────────────────────────────────────────────────────────────┤
│                  通信层 (RPC / HTTP / SSE)                    │
│   TUI ↔ Worker: 直接 RPC (无 HTTP 开销)                      │
│   Web/Desktop ↔ Server: HTTP + SSE 实时推送                   │
├──────────────────────────────────────────────────────────────┤
│                    后端服务层 (Hono)                           │
│   REST API + OpenAPI  │  WebSocket (PTY)  │  SSE (事件流)     │
├──────────────────────────────────────────────────────────────┤
│                    核心业务层                                  │
│   Agent 系统  │  Session 管理  │  Tool 执行  │  Provider 集成  │
├──────────────────────────────────────────────────────────────┤
│                    基础设施层                                  │
│   SQLite + Drizzle ORM  │  Config  │  Permission  │  LSP/MCP │
└──────────────────────────────────────────────────────────────┘
```

**技术栈概要：**
- **运行时**: Bun
- **构建工具**: Turbo (monorepo 任务编排)
- **LLM 集成**: Vercel AI SDK (23+ provider)
- **UI 框架**: SolidJS (TUI 和 Web 共用)
- **数据库**: SQLite (WAL 模式) + Drizzle ORM
- **HTTP 框架**: Hono
- **包管理**: Bun monorepo

## 2. 入口点与 CLI 命令系统

### 2.1 启动流程

入口文件：`packages/opencode/src/index.ts`

```
process.argv
    ↓
yargs 解析器（脚本名 "opencode"）
    ↓
全局中间件：
  - Log.init() 初始化日志
  - 设置环境变量 AGENT=1, OPENCODE=1
  - 首次运行：SQLite 数据迁移（从旧版 JSON 格式）
    ↓
命令匹配 → builder (选项解析) → handler (命令执行)
    ↓
process.exit()
```

### 2.2 命令列表

| 命令 | 作用 | 说明 |
|------|------|------|
| `opencode [project]` | 默认命令：启动 TUI | 交互式终端 UI |
| `opencode serve` | 无头 API 服务器 | 默认端口 4096，需设置密码 |
| `opencode web` | Web UI | 启动服务器并打开浏览器 |
| `opencode run [message..]` | 批量执行 | 非交互模式，支持 stdin |
| `opencode attach <url>` | 远程连接 | 连接到运行中的 OpenCode 服务器 |
| `opencode acp` | Git 自动化 | Amend/Commit/Push |
| `opencode pr <number>` | PR 助手 | 检出 PR 并导入 session |
| `opencode auth <sub>` | 认证管理 | login/logout/list |
| `opencode models [provider]` | 模型列表 | 查看可用模型 |
| `opencode mcp <sub>` | MCP 管理 | add/list/auth/logout/debug |
| `opencode session <sub>` | Session 管理 | list/delete |
| `opencode agent <sub>` | Agent 管理 | create/list |
| `opencode export/import` | 导入导出 | Session 数据共享 |
| `opencode github <sub>` | GitHub 集成 | Actions webhook 集成 |
| `opencode debug <sub>` | 调试工具 | config/lsp/ripgrep/file/snapshot 等 |
| `opencode upgrade` | 升级 | 更新 OpenCode |
| `opencode generate` | 生成 | OpenAPI spec 生成 |

### 2.3 Bootstrap 引导

所有命令通过 `bootstrap(directory, callback)` 初始化：
- 建立 Instance 上下文（项目、工作区）
- 检测项目类型（git/非git）
- 加载配置
- 确保清理（`Instance.dispose()`）

## 3. Agent 系统

### 3.1 Agent 类型

| Agent | 模式 | 用途 |
|-------|------|------|
| **build** | primary | 默认 Agent，可执行代码修改 |
| **plan** | primary | 只读规划模式，禁用编辑工具 |
| **general** | subagent | 通用子代理，用于并行研究 |
| **explore** | subagent | 快速代码库探索 |
| **compaction** | 系统(隐藏) | 自动摘要对话历史 |
| **title** | 系统(隐藏) | 生成 session 标题 |
| **summary** | 系统(隐藏) | 生成 session 摘要 |

### 3.2 Agent 配置属性

```typescript
Agent.Info = {
  name: string,           // 唯一标识
  description: string,    // 描述
  mode: "primary" | "subagent" | "all",
  permission: Ruleset,    // 工具权限
  model: string,          // 默认模型 (providerID/modelID)
  variant: string,        // 模型变体
  prompt: string,         // 系统提示词
  temperature: number,
  topP: number,
  steps: number,          // 最大迭代步数
  hidden: boolean,        // 是否在 UI 中隐藏
}
```

### 3.3 Agent 循环（核心）

```
用户消息
    ↓
SessionPrompt.loop() 启动
    ↓
┌─────────────────────────────────┐
│ 1. 加载消息历史（过滤已压缩的）   │
│ 2. 确定当前 Agent 和模型         │
│ 3. 解析可用工具（权限过滤）       │
│ 4. 构建系统提示词                │
│ 5. 转换消息为 ModelMessage 格式  │
│ 6. 调用 LLM.stream()            │
│ 7. 处理流式输出                  │
│    ├─ 文本 → 保存 TextPart      │
│    ├─ 工具调用 → 执行并返回结果   │
│    └─ 推理 → 保存 ReasoningPart │
│ 8. 检查上下文是否溢出            │
│ 9. finish_reason == "tool-calls" │
│    → 回到步骤 1 继续循环          │
│    finish_reason == "stop"       │
│    → 退出循环                    │
└─────────────────────────────────┘
    ↓
返回最终 Assistant 消息
```

## 4. Session 管理

### 4.1 Session 生命周期

```
创建 → 活跃（消息交互）→ 压缩（上下文溢出时）→ 归档/删除
         ↑                                    │
         └──── fork（分支） ←──────────────────┘
```

- **创建**：`Session.createNext()` → SQLite 记录，含 slug/title/version
- **Fork**：复制消息历史到新 session
- **Revert**：撤销文件更改，恢复到特定消息点
- **归档/删除**：CASCADE 删除所有消息和 parts

### 4.2 消息格式 (MessageV2)

每条消息包含多个 **Part**：

| Part 类型 | 说明 |
|-----------|------|
| **TextPart** | 文本内容 |
| **ToolPart** | 工具调用（状态：pending → running → completed/error）|
| **ReasoningPart** | LLM 推理过程（扩展思考）|
| **FilePart** | 附件文件（图片、PDF 等）|
| **SnapshotPart** | 文件系统快照（git 状态）|
| **PatchPart** | Git diff 变更 |
| **StepStartPart / StepFinishPart** | 迭代边界标记 |
| **AgentPart** | 子 Agent 调用标记 |
| **SubtaskPart** | 子任务调用 |
| **CompactionPart** | 压缩请求 |

### 4.3 上下文压缩 (Compaction)

当 token 用量接近模型上下文限制时自动触发：

```
检测：tokens_used >= context_limit - reserved_buffer (默认 20K)
    ↓
裁剪阶段 (Prune)：
  - 从后向前扫描消息历史
  - 标记旧的工具输出为 "compacted"
  - 保留最近 2 个 turn
    ↓
压缩阶段 (Compaction)：
  - 运行隐藏的 compaction Agent
  - 生成详细摘要文档
  - 创建合成的后续用户消息
    ↓
继续对话（以摘要为新上下文）
```

### 4.4 系统提示词构建

按优先级层叠：
1. 环境信息（模型名、平台、工作目录、git 状态、日期）
2. Provider 专用提示（Anthropic/OpenAI/Gemini 各有不同）
3. 项目指令（CLAUDE.md / AGENTS.md / CONTEXT.md，沿目录树向上查找）
4. 全局指令（`~/.claude/CLAUDE.md` 或配置文件）
5. 用户消息中的自定义 system
6. Agent 自定义 prompt

## 5. Tool 系统

### 5.1 工具定义模式

```typescript
Tool.define("tool-id", {
  description: "...",
  parameters: z.object({...}),    // Zod schema 验证
  async execute(params, ctx) {
    // ctx.ask()  → 请求权限
    // ctx.metadata() → 更新 UI 状态
    // ctx.abort → 取消信号
    return { title, metadata, output, attachments? }
  }
})
```

### 5.2 可用工具

| 类别 | 工具 | 说明 |
|------|------|------|
| **文件操作** | bash | Shell 命令执行，超时控制，流式输出 |
| | read | 读文件/目录，支持分页、二进制检测、图片/PDF |
| | write | 写文件，LSP 诊断，diff 生成 |
| | edit | 编辑文件，多种匹配策略（简单/行修剪/块锚定/模糊） |
| | glob | 文件模式匹配（ripgrep） |
| | grep | 内容搜索，正则支持（ripgrep） |
| **Web/搜索** | websearch | 网页搜索（Exa MCP API） |
| | codesearch | 代码片段搜索（Exa MCP API） |
| | webfetch | 网页抓取，HTML → Markdown 转换 |
| **任务/Agent** | task | 创建子任务，指定子 Agent |
| | question | 向用户提问，结构化问题 |
| | skill | 加载专业技能指令集 |
| **实用** | todowrite | 更新待办列表 |
| | lsp | LSP 操作（跳转定义、查找引用等），实验性 |
| | apply_patch | 应用补丁（特定 GPT 模型） |
| | batch | 批量工具执行，实验性 |
| **扩展** | Plugin 工具 | 从配置目录加载的自定义工具 |
| | MCP 工具 | MCP 服务器提供的动态工具 |

### 5.3 工具执行生命周期

```
LLM 返回 tool_call
    ↓
Zod 参数验证
    ↓
创建 Tool.Context (sessionID, abort, messages...)
    ↓
Plugin hook: tool.execute.before
    ↓
权限检查 (ctx.ask())
  ├─ allow → 继续
  ├─ deny → 抛出 RejectedError
  └─ ask → 发布事件，等待用户批准
    ↓
tool.execute(args, ctx)
    ↓
输出截断（MAX_LINES=2000, MAX_BYTES=50KB）
  └─ 超出部分保存到文件
    ↓
Plugin hook: tool.execute.after
    ↓
结果返回给 LLM → 循环继续
```

### 5.4 死循环检测 (Doom Loop)

Agent 连续 3 次以相同参数调用同一工具时触发检测，请求用户确认是否继续。

## 6. Provider 系统（多 LLM 集成）

### 6.1 支持的 Provider（23+）

通过 Vercel AI SDK 捆绑的 Provider：
- **Anthropic** (Claude)、**OpenAI** (GPT)、**Google** (Gemini)
- **Azure**、**Amazon Bedrock**、**Google Vertex**
- **GitHub Copilot**、**xAI** (Grok)、**Mistral**
- **Groq**、**DeepInfra**、**Cerebras**、**Cohere**
- **TogetherAI**、**Perplexity**、**OpenRouter**
- **Vercel**、**GitLab**、**Cloudflare AI Gateway**
- **OpenAI Compatible**（自定义端点）

### 6.2 Provider 初始化流程

```
1. 加载 models.dev 快照 → 获取 Provider 和 Model 元数据
    ↓
2. 合并配置 → opencode.json 中的 provider 设置
    ↓
3. 加载凭证：
   ├─ 环境变量 (ANTHROPIC_API_KEY 等)
   ├─ Auth 存储 (数据库中的密钥)
   ├─ Plugin 提供的认证
   └─ 配置文件中的 API key
    ↓
4. 应用自定义加载器（Provider 特定逻辑）：
   ├─ Anthropic: 注入 beta headers
   ├─ OpenAI: 切换 .responses() / .chat()
   ├─ Bedrock: 区域前缀逻辑
   ├─ Vertex: Google Auth token
   └─ ...
    ↓
5. 缓存 SDK 实例（按 hash 复用）
```

### 6.3 模型选择优先级

1. 请求中显式指定的 model
2. 最后一条用户消息中的 model
3. Agent 默认模型
4. Provider 第一个模型
5. 全局默认 `Provider.defaultModel()`

### 6.4 LLM 调用流程

```typescript
LLM.stream({
  model,              // 选定的模型
  system,             // 系统提示词数组
  messages,           // 转换后的消息历史
  tools,              // 可用工具
  toolChoice,         // "auto" | "required"
  abort,              // 取消信号
})
  ↓
wrapLanguageModel() → 应用 Provider Transform 中间件
  ↓
ai.streamText() → Vercel AI SDK 流式调用
  ↓
流式返回：textDelta, toolCalls, finishReason, tokens
```

### 6.5 Token 计费

```
cost = (input × input_price) + (output × output_price)
     + (cache_read × cache_read_price) + (cache_write × cache_write_price)
```

## 7. Server 系统（HTTP API）

### 7.1 Hono Web 框架

- **端口**: 默认 4096，可配置
- **安全**: Basic Auth（`OPENCODE_SERVER_PASSWORD`），CORS 白名单
- **发现**: mDNS 服务发现（可选）

### 7.2 核心 API 路由

| 端点 | 用途 |
|------|------|
| `GET /event` | SSE 事件流（心跳 10s，实时推送所有事件） |
| `POST /session/:id/message` | 发送消息（流式返回 LLM 响应） |
| `POST /session/:id/prompt_async` | 异步发送消息（立即返回 204） |
| `POST /session/:id/command` | 执行工具命令 |
| `POST /session/:id/shell` | 执行 Shell 命令 |
| `POST /session/:id/fork` | Fork session |
| `POST /session/:id/revert` | 撤销变更 |
| `GET /session/:id/message` | 获取消息历史 |
| `GET /provider/` | 获取可用 Provider 列表 |
| `POST /provider/:id/oauth/*` | OAuth 认证流程 |
| `GET /pty/:id/connect` | WebSocket PTY 连接 |
| `GET /config` | 配置管理 |
| `/mcp`, `/permission`, `/agent`, `/skill` 等 | 其他管理接口 |

### 7.3 Instance 上下文中间件

每个请求通过中间件建立项目上下文：
```typescript
const directory = query("directory") || header("x-opencode-directory") || process.cwd()
Instance.provide({ directory, init: InstanceBootstrap, fn: () => next() })
```

## 8. TUI 渲染系统

### 8.1 架构

```
主进程 (TUI 渲染)
  ├─ SolidJS + @opentui/solid (60 FPS 终端渲染)
  ├─ 嵌套 Context Providers:
  │   ExitProvider → KVProvider → ToastProvider → RouteProvider
  │   → SDKProvider → SyncProvider → ThemeProvider → KeybindProvider
  │   → Dialog/Command/Prompt providers
  └─ 事件驱动的响应式更新
        ↑ RPC 通信
Worker 进程 (后端逻辑)
  ├─ Hono Server (可选 HTTP)
  ├─ Agent 编排
  └─ Session 管理
```

### 8.2 通信模式

| 模式 | 场景 | 说明 |
|------|------|------|
| **直接 RPC** | 默认 TUI | Worker 线程直接通信，无 HTTP 开销 |
| **HTTP + SSE** | 指定 port/hostname 时 | 标准 HTTP 调用 + SSE 事件推送 |

RPC 协议：
```
请求: { type: "rpc.request", method: "fetch", input: {...}, id: 1 }
响应: { type: "rpc.result", result: {...}, id: 1 }
事件: { type: "rpc.event", event: "event", data: {...} }
```

### 8.3 事件流与状态同步

```
后端事件 (Bus.publish)
    ↓
SSE / RPC 传输
    ↓
SDK EventSource 接收
    ↓
事件批处理 (16ms 窗口去抖)
    ↓
SyncProvider 更新 SolidJS Store
    ↓
响应式组件自动重渲染
    ↓
OpenTUI 60 FPS 终端输出
```

- **路径**: `~/.opencode/opencode.db`

## 11. 权限系统

### 11.1 三级权限结构

```
1. 全局动作: "allow" | "deny" | "ask"
2. 按工具: { "read": "allow", "bash": "deny" }
3. 模式匹配: { "bash": { "/safe/**": "allow", "/dangerous/**": "deny" } }
```

### 11.2 权限流程

```
工具请求执行
    ↓
合并规则集（Agent 默认 + Session 覆盖）
    ↓
匹配规则评估（最后匹配的规则生效）
    ↓
├─ "allow" → 立即执行
├─ "deny"  → 抛出 RejectedError
└─ "ask"   → 发布事件，等待用户响应
              ├─ "once"   → 单次批准
              ├─ "always" → 记住此模式
              └─ "reject" → 拒绝
```

## 12. MCP 系统（Model Context Protocol）

- OpenCode 作为 MCP **客户端**连接到服务器
- 传输类型：
  - **远程 HTTP/SSE**: StreamableHTTP / SSE
  - **本地 stdio**: 启动本地进程
- 提供：工具 (Tools)、提示模板 (Prompts)、资源 (Resources)
- 支持 OAuth 认证流程
- MCP 工具动态注入到 Agent 可用工具列表

---

## 13. LSP 系统（Language Server Protocol）

- OpenCode 运行 LSP **客户端**连接到语言服务器
- 内置支持：TypeScript, Deno, Vue, Python (Pyright), Rust, Go, HTML, CSS 等
- 功能：悬停信息、跳转定义、查找引用、文档符号、工作区符号、调用层次
- 延迟初始化：首次访问文件时启动对应服务器
- 诊断去抖：150ms
- 用途：读取/编辑文件后自动收集诊断信息，辅助 Agent 理解代码

## 14. 完整数据流：从用户输入到响应展示

```
[1] 用户在 TUI 输入消息并提交
    ↓
[2] Prompt 组件收集输入（文本 + 附件 + Agent + 模型选择）
    ↓
[3] SDK 客户端调用: POST /session/:id/message
    ↓
[4] SessionPrompt.prompt() 创建用户消息
    ↓
[5] SessionPrompt.loop() 启动 Agent 循环
    ↓
[6] 构建上下文：
    ├─ 加载消息历史（过滤已压缩部分）
    ├─ 解析可用工具（权限过滤）
    ├─ 构建系统提示词（环境 + 指令 + Agent prompt）
    └─ 转换消息格式（MessageV2 → ModelMessage）
    ↓
[7] LLM.stream() 调用 Vercel AI SDK
    ├─ Provider SDK 实例化（缓存复用）
    ├─ Provider Transform 中间件应用
    └─ streamText() 流式调用
    ↓
[8] 流式处理：
    ├─ 文本块 → Bus.publish("message.part.updated")
    ├─ 工具调用 → 执行工具 → 结果返回 LLM
    └─ 推理内容 → 保存 ReasoningPart
    ↓
[9] 事件通过 SSE/RPC 传输到前端
    ↓
[10] SyncProvider 接收事件 → 更新 SolidJS Store
    ↓
[11] 响应式组件重渲染 → OpenTUI 60 FPS 输出到终端
    ↓
[12] 如果 finish_reason == "tool-calls"，回到 [5] 继续循环
     如果 finish_reason == "stop"，完成
```

## 15. 关键设计模式

| 模式 | 应用 |
|------|------|
| **事件驱动** | Bus pub/sub 贯穿全局，SSE 实时推送，SolidJS 响应式 |
| **Instance 上下文** | 每个项目独立的状态隔离，请求级事务管理 |
| **延迟初始化** | Provider SDK、LSP 服务器、MCP 连接均按需创建 |
| **缓存复用** | SDK 实例按 hash 缓存，模型元数据定时刷新 |
| **权限守卫** | 工具执行前必须通过权限检查，支持记忆决策 |
| **输出截断** | 工具输出 > 50KB/2000行自动截断并保存完整输出到文件 |
| **上下文压缩** | 自动检测溢出 → 裁剪旧输出 → LLM 摘要 → 继续对话 |
| **Plugin Hook** | tool.definition / tool.execute.before / tool.execute.after |
| **错误恢复** | 指数退避重试、上下文溢出自动压缩、死循环检测 |
